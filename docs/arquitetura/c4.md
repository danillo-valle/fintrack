# Arquitetura do FinTrack em C4

Três níveis do modelo [C4](https://c4model.com): o **contexto** (quem usa e com quem o sistema
fala), os **contêineres** (o que roda no servidor de casa) e os **componentes** do app web (como o
código se divide). O caminho de cada tela até o banco, tirado do código, está no mapa do fluxo
(`docs/arquitetura/fluxo.json`, gerado pelo `packages/flow-map`) e no site
[FinTrack por dentro](https://danillo-valle.github.io/fintrack/).

Os diagramas são texto (Mermaid): o GitHub os desenha aqui mesmo, e o site os transforma em
imagem a cada versão. Um diagrama que não desenha quebra o build do site (ADR-023).

Legenda: azul-escuro é pessoa; azul é o FinTrack (sistema, contêiner ou componente); cinza com
borda tracejada é de fora; o cilindro é onde os dados ficam.

## Nível 1 · Contexto

```mermaid
flowchart TB
  classDef pessoa fill:#0E1F5C,stroke:#0E1F5C,color:#FFFFFF
  classDef sistema fill:#1F43D6,stroke:#1F43D6,color:#FFFFFF
  classDef fora fill:#E4E8F5,stroke:#535C78,color:#0E1325,stroke-dasharray:5 3

  pessoa["<b>Pessoa da casa</b><br/>[Pessoa]<br/>Lança, revisa e acompanha<br/>o dinheiro da casa"]:::pessoa
  cloudflare["<b>Cloudflare</b><br/>[Sistema de fora]<br/>Túnel, DNS e HTTPS"]:::fora
  fintrack["<b>FinTrack</b><br/>[Sistema]<br/>Controle financeiro pessoal e da casa,<br/>no servidor de casa"]:::sistema
  pluggy["<b>Meu Pluggy</b><br/>[Sistema de fora]<br/>Open Finance: contas,<br/>cartões e faturas"]:::fora
  bots["<b>WhatsApp (Meta) e Telegram</b><br/>[Sistemas de fora]<br/>O bot de lançamento"]:::fora
  hibp["<b>Have I Been Pwned</b><br/>[Sistema de fora]<br/>Senhas vazadas"]:::fora
  email["<b>E-mail (SMTP)</b><br/>[Sistema de fora]<br/>Confirmação, convite, senha"]:::fora
  github["<b>GitHub</b><br/>[Sistema de fora]<br/>Código, CI e as imagens (GHCR)"]:::fora

  pessoa -- "Usa pelo navegador (HTTPS)" --> cloudflare
  cloudflare -- "Túnel de saída, sem porta aberta" --> fintrack
  pessoa -- "Manda mensagens" --> bots
  bots -- "Webhook assinado; respostas" --> fintrack
  fintrack -- "Busca uma vez por dia (HTTPS)" --> pluggy
  fintrack -- "Confere senha nova (5 caracteres do hash)" --> hibp
  fintrack -- "Manda e-mails" --> email
  fintrack -- "Puxa a versão nova a cada minuto" --> github
```

- **Uma pessoa, muitas casas**: cada pessoa tem o seu ambiente e participa de um lar; ambientes
  compartilhados juntam os gastos de várias pessoas (ADR-004, ADR-006).
- **Nada entra na rede de casa**: o túnel da Cloudflare é uma conexão de saída, e o deploy é
  puxado pelo servidor (ADR-005).
- **Só o necessário sai**: do HIBP vão 5 caracteres do hash; do bot, só a resposta; o número de
  quem escreve fica como HMAC (ADR-018, ADR-022).

## Nível 2 · Contêineres

```mermaid
flowchart TB
  classDef pessoa fill:#0E1F5C,stroke:#0E1F5C,color:#FFFFFF
  classDef conteiner fill:#1F43D6,stroke:#1F43D6,color:#FFFFFF
  classDef dados fill:#DCE5FF,stroke:#1F43D6,color:#0E1325
  classDef fora fill:#E4E8F5,stroke:#535C78,color:#0E1325,stroke-dasharray:5 3

  pessoa["<b>Pessoa da casa</b><br/>[Pessoa]"]:::pessoa

  subgraph servidor["Servidor de casa: Ubuntu 24.04, Docker Compose (fintrack-prod)"]
    cloudflared["<b>cloudflared</b><br/>[Contêiner]<br/>A ponta do túnel"]:::conteiner
    caddy["<b>Caddy</b><br/>[Contêiner]<br/>HSTS, log de acesso,<br/>o IP de quem visita"]:::conteiner
    web["<b>App web</b><br/>[Contêiner: Next.js 16, Node 24]<br/>Telas, Server Actions, webhooks do bot<br/>e os trabalhadores das filas (pg-boss)"]:::conteiner
    migrate["<b>migrate</b><br/>[Contêiner: Prisma CLI]<br/>Aplica as migrações no deploy"]:::conteiner
    db[("<b>Postgres 17</b><br/>[Contêiner: banco]<br/>Dados, auditoria e as filas")]:::dados
    ml["<b>Serviço Python</b><br/>[Contêiner: FastAPI]<br/>Fatura em PDF, classificador,<br/>a ponte da IA local"]:::conteiner
    llm["<b>LLM local</b><br/>[Contêiner: llama-server]<br/>Qwen2.5 3B, só das 04:40 às 06:45"]:::conteiner
    timers["<b>Timers do systemd</b><br/>[Processos do servidor]<br/>Deploy a cada minuto, backup às 03:30,<br/>liga e desliga o LLM"]:::conteiner
  end

  ghcr["<b>GHCR</b><br/>[De fora]<br/>As imagens web, migrate e ml"]:::fora
  drive["<b>Google Drive</b><br/>[De fora]<br/>A cópia do backup, cifrada com age"]:::fora
  terceiros["<b>Meu Pluggy, Meta, Telegram,<br/>HIBP e SMTP</b><br/>[De fora]"]:::fora

  pessoa -- "HTTPS pela Cloudflare" --> cloudflared
  cloudflared --> caddy
  caddy -- "HTTP na rede entrada" --> web
  web -- "SQL na rede dados" --> db
  web -- "HTTP com token curto (rede ml)" --> ml
  ml -- "HTTP (rede llm)" --> llm
  migrate --> db
  web -- "HTTPS" --> terceiros
  timers -- "Puxa a imagem nova" --> ghcr
  timers -- "pg_dump cifrado" --> drive

  style servidor fill:#F6F8FE,stroke:#8C95B0
```

- **Redes separadas**: o Caddy só alcança o app (`entrada`); o banco só o app e o `migrate`
  (`dados`); o serviço Python só o app (`ml`); o LLM só o serviço Python (`llm`). Nenhum
  contêiner publica porta (ADR-005, ADR-014, ADR-016).
- **Deploy com volta automática**: o timer baixa a imagem, faz o backup, migra, troca o app e
  confere o `/api/health` com o commit novo; se não responder, volta (ADR-005).
- **As filas moram no Postgres** (pg-boss): seis filas, com quem põe trabalho em cada uma no
  mapa do fluxo (ADR-011).

## Nível 3 · Componentes do app web

```mermaid
flowchart TB
  classDef comp fill:#1F43D6,stroke:#1F43D6,color:#FFFFFF
  classDef puro fill:#DCE5FF,stroke:#1F43D6,color:#0E1325
  classDef fora fill:#E4E8F5,stroke:#535C78,color:#0E1325,stroke-dasharray:5 3

  subgraph navegador["No navegador"]
    ui["<b>Componentes do navegador</b><br/>features/*/ui, components/ (use client)<br/>Formulários, modais, o cliente do Better Auth"]:::comp
  end

  subgraph servidor["No servidor (Next.js)"]
    telas["<b>Telas e rotas</b><br/>app/ (page, layout, route)<br/>Pedem a sessão e carregam os dados"]:::comp
    auth["<b>Better Auth</b><br/>lib/auth.ts, /api/auth<br/>Senha, 2FA, passkey, HIBP"]:::comp
    acoes["<b>Server Actions e consultas</b><br/>features/*/server<br/>zod, crachá, operação, financeChanged"]:::comp
    apoio["<b>Acesso, cache e filas</b><br/>lib/access, lib/finance-cache, lib/jobs<br/>crachá, use cache, pg-boss e o bot"]:::comp
  end

  subgraph pacotes["Pacotes do monorepo"]
    core["<b>packages/core</b><br/>Regras puras, sem I/O:<br/>dinheiro, datas, cartão, orçamento"]:::puro
    dbpkg["<b>packages/db</b><br/>Prisma 7, crachás, operações<br/>com auditoria na mesma transação"]:::comp
    importers["<b>packages/importers</b><br/>Meu Pluggy, OFX, o cliente do PDF"]:::comp
  end

  pg[("<b>Postgres</b>")]:::puro
  fora["<b>Serviço Python, Meu Pluggy,<br/>Meta, Telegram, SMTP</b>"]:::fora

  ui -- "GET da página" --> telas
  ui -- "POST da Server Action" --> acoes
  ui -- "fetch /api/auth" --> auth
  telas -- "Carrega" --> acoes
  acoes --> apoio
  acoes --> core
  acoes --> dbpkg
  acoes --> importers
  apoio --> dbpkg
  auth --> dbpkg
  dbpkg --> pg
  importers --> fora
  apoio -- "Respostas do bot, e-mail" --> fora

  style navegador fill:#F6F8FE,stroke:#8C95B0
  style servidor fill:#F6F8FE,stroke:#8C95B0
  style pacotes fill:#F6F8FE,stroke:#8C95B0
```

- **A fronteira do navegador é o `"use client"`**: o que roda no aparelho só chama o servidor por
  Server Action (POST da própria página) ou pelo Better Auth (`/api/auth`). O mapa do fluxo lista,
  por tela, os componentes do navegador, o que ela carrega e as actions dos formulários.
- **Banco só em `features/*/server` e `lib`** (regra do ESLint); **tudo que toca uma carteira
  passa pelo crachá** tipado (ADR-006), e o mapa confere que toda tela e toda action pedem a
  sessão.
- **Regra de negócio em `packages/core`**, pura e testada (inclusive por propriedade); o banco
  repete as regras críticas em CHECK e gatilho (ADR-004).
